# CS 230 - Software Design Document

## Project Reflection

### 1. Project Summary

The Gaming Room was the client for this project. They wanted to make their game called Draw It or Lose It available on different devices. The game needed to allow multiple teams and players to play. Also, each game, team, and player needed their own ID. My job was to help plan the software so the game could work on different platforms.

### 2. What I Did Well

I think I did a good job explaining the different parts of the project. I tried to keep my information clear and organized so it would be easy to understand. Also, I think I did well comparing the different platforms and explaining which one would work better for the game.

### 3. How the Design Document Helped Me

The design document helped me understand what I needed to do before starting the code. For example, it helped me see how the classes work together and what each part of the application does. I think having everything planned first makes coding easier and helps avoid mistakes.

### 4. What I Would Improve

If I could change something, I would improve the security part of my document. I would explain more about how to keep player information safe and how to protect the game from problems. I think adding more details would make my document better.

### 5. Understanding the User's Needs

First, I looked at what The Gaming Room wanted for their game. They needed a game that could work on different devices and allow different players and teams to join. I used this information to help plan the software. I think understanding what the client wants is important because it helps developers create something that actually works for the users.

### 6. My Approach to Software Design

I started by reading the project instructions and understanding what the client needed. Then, I worked on the different parts of the design document and compared the available options. In the future, I would follow a similar process. I would also spend more time checking my work and testing different options before making a final decision.
